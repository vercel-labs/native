Native SDK builds native apps from HTML, CSS and TypeScript. Its compiler, the `native` CLI, compiles the HTML and CSS ahead of time, and [scriptc](https://scriptc.dev) compiles the TypeScript, both your app's and the SDK's runtime, to machine code. The result is a small native app bundle — an executable with the images, fonts and other files it reads — that runs without a browser, webview or JavaScript engine.

Native SDK is experimental and supports a subset of HTML, CSS and the DOM. Run `native check` on an app to see what it uses that isn't supported, and read [Supported HTML](/reference/supported-html), [Supported CSS](/reference/supported-css) and [Supported DOM](/reference/supported-dom) for the details. It builds on macOS, Linux and Windows: the windowed host is macOS's and Win32's, and on Linux the same pages run headlessly, which is how the web-platform tests run.

## Install

Install with Node.js 24 or later. On macOS the Xcode command line tools provide the compiler (`xcode-select --install`); on Linux the host's libraries and a C compiler are listed in [Shipping a Linux app](https://github.com/vercel-labs/native/blob/next/packages/cli/docs/linux.md); and on Windows `zig` on the `PATH` builds scriptc's link and the Win32 host.

Install the CLI into your app's project:

```console
$ npm install -D @native-sdk/cli
```

Run it through your package.json scripts, with `npm run dev` and `npm run build`:

```json
{
  "scripts": {
    "dev": "native dev",
    "build": "native build"
  }
}
```

For a one-off command, run the package by its name, as `npx @native-sdk/cli <command>`.

## Build an app

An app is an HTML page with its stylesheets and scripts, in a directory of its own. It doesn't have to live in the Native SDK repository. [Getting started](/getting-started) walks through a complete app. The short version:

```console
$ npm run build
$ ./hello
```

`npx @native-sdk/cli run` builds and runs in one step. `npm run dev` (`native dev`) watches the app and applies HTML and CSS edits to the open window in place; a TypeScript edit rebuilds and relaunches it. See the [live editing guide](/guides/live-editing).

The [examples](https://github.com/vercel-labs/native/tree/next/examples) are:

- `counter`: a counter whose buttons change a heading.
- `todo`: a todo list with an input and an Add button, and headless-test steps.
- `article`: an article with inline formatting, a link and headings.
- `dashboard`: a sidebar, stat cards and a members table.
- `canvas`: an animated canvas piece.
- `canvas-particles`: a particle field drawn on a canvas.
- `webgl-cube`: a spinning WebGL 2 cube.
- `webgl-texture`: a WebGL 2 quad textured from a file.
- `css-motion`: `@keyframes` and transitions.
- `preact-todo`: a todo list in Preact.
- `ime`: an input method composing marked text in a field.
- `three-game`: a playable three.js arcade game.
- `three-hero`: a lit, textured torus knot drawn with three.js.
- `ui-dashboard`: a React 19 and Tailwind 4 dashboard built with UI SDK parts.
- `ui-settings`: a React 19 and Tailwind 4 settings app built with UI SDK parts.
- `halyard`: a React 19 issue tracker built with UI SDK parts, with a command palette and drag to reorder.
- `player`: a music library and player with album art, a searchable track list and a working player bar.

## Test an app

Apps can run headlessly, driven by scripted input, and save a screenshot:

```console
$ NATIVE_STEPS='click #wave | print #greeting' NATIVE_SNAPSHOT=out.png ./hello
Hello, native
```

The [headless testing guide](/guides/headless-testing) covers steps, snapshots and the environment variables that control a run.
